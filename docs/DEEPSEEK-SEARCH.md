# DeepSeek web search

Open **Extensions → Connections → Web search** and save a separate DeepSeek API key. This connection is independent of model API accounts and doesn't borrow their keys or environment variables on its own. If you already added a DeepSeek API card, its row under **Usage & connections → Connections** shows whether web search is connected and offers **Use this key for web search**: only when you select it, PugPort copies that card's key into the web-search credential on the local server, without sending it to the window. Later changes to the card's key don't change the search key. Saving a key enables this connection without making a paid test request. Clear the key or turn the connection off to revoke it, including active searches.

## Use it

- Enter `/search latest DeepSeek release notes` in a conversation, or the Chinese command name `/搜索` (for example `/搜索 DeepSeek 最新更新`, "latest DeepSeek updates"). The command searches directly, preserves source links and summaries, then gives the question and those sources to the normal CLI/API router to answer. Automatic mode chooses an executor; a manual executor, model, effort, channel and budget keep their existing limits. Search itself still works without an answer executor, with an explicit notice that the sources could not be turned into an answer.
- Explicit Chinese requests such as `用 DS 搜一下今天的天气` ("use DS to look up today's weather") or `用搜索功能查一下最新更新` ("use search to check the latest updates") use the same search-and-answer flow. The original question, background and restrictions stay together. Quoted commands, explanations and requests that forbid searching do not trigger this shortcut.
- In ordinary tasks, an authorized agent can choose `web_search` when it needs current information and `web_fetch` to read a public source page. Ordinary greetings and self-contained replies don't trigger a search automatically.
- Explicit restrictions such as "Do not use web search" or its Chinese equivalent "不要联网" ("don't go online") withhold these tools. A local user steering message can revoke the active search permission without stopping unrelated file tools. Parent task restrictions and project rules also apply to delegated searches.

The slash command accepts a question or keywords and the conversation text you explicitly quote. For example, quote a list of laptop models and send `/搜索 给我网址，和成本` ("give me the websites and the costs"); the selected subjects supply the search context, and the answer keeps the numbered quotes and your notes. The original question, quote text, note and source message ID remain in the conversation. Quoted text stays reference material and cannot grant permissions or override routing; source message IDs do not authorize reading another conversation or a file. File and image attachments still need to be removed before a direct search.

You can type your question first, move the caret to the beginning and enter `/` to open the command menu. Selecting search inserts `/搜索 ` (the Chinese command name) and preserves the existing question, including its spaces and line breaks. The menu uses the text before the caret; slashes inside ordinary text or URLs do not open it. Selecting a command does not send the message.

Explicit device, external-agent and custom-role requests keep their existing dispatch. A retry with the same client message ID returns the existing search and answer task. It does not search or answer twice. Answering uses the already fetched, bounded sources and quotes as untrusted evidence and defaults to answering directly in read-only mode, without a plan or file changes. This answer task cannot call DeepSeek Search/Fetch again. A failed send restores both the question and its quoted draft.

Follow-up searches such as “Is it still worth it in 2027?” can use an explicit topic from the same conversation's last six messages. After a discussion of a specific laptop model, the actual search includes that model rather than a generic query. An explicit current subject takes priority, followed by the text selected for this message, then the existing same-conversation history rules. Only short, literal topic names and the current question's terms go to Search; the full transcript, quoted webpages, code and old instructions do not. Lists asking for their websites or costs can keep multiple selected names; an unresolved singular reference still asks for clarification without a paid search. A new explicit subject or a topic switch keeps the old subject out. The saved search record retains both the original question and the actual query, capped at 128 characters; routing receives the original question and user notes, while the answer also receives the quoted evidence.

Use **Turn into an answer** on a completed older search, or one whose answer could not start, to answer from its saved sources without searching again. This follows the conversation's current executor selection and normal routing rules. Repeated clicks reuse an existing answer task, including a completed or cancelled one. Interrupted searches and answers never restart automatically after an app restart; failed searches cannot create an answer task.

## Spending and records

The default local monthly estimate limit is **CNY 5**, and can be changed or set to zero. A successful nonempty Search or Fetch request is estimated at **CNY 0.005** under the official price checked on 2026-10-24. Failed or empty responses aren't counted as billable. Search charges are independent of model token usage. The month boundary uses UTC.

The service reserves one request's estimate before network access, limits concurrent requests, and makes no automatic retries. If cancellation, timeout, malformed data or transport loss leaves the provider outcome unknown, the reservation remains visible as unconfirmed. Outstanding reservations carry across restarts and month changes. These are conservative local estimates, not the provider invoice or a provider-enforced hard limit.

Search replies include source, duration and estimated cost. Agent calls also retain arguments, status and bounded results in the existing run audit. Source material is untrusted data and doesn't authorize new actions. Completed direct search results can be used as labeled context in later messages.

Keys are stored through PugPort's private credential writer outside the chat database and synced data directory. Settings, usage counters and receipts contain no key. The network destination is fixed to DeepSeek's Search/Fetch endpoints; the app doesn't fetch target pages directly or accept an arbitrary search-service endpoint. Results and response bodies have size limits; errors don't echo upstream credential-bearing bodies.

Reference: [official Search/Fetch guide and pricing](https://api-docs.deepseek.com/guides/search/).
