# User guides

Step-by-step guides to setting up and using PugPort every day. Every section reflects what is implemented currently.

- [Getting started](getting-started.md) — install from source on Windows, macOS and Linux, launch the app, add CLI subscriptions, second accounts and API keys, and read the **Usage** page.
- [Chat and mentions](chat-and-mentions.md) — send messages, steer running tasks, manage the queue, use `/` commands, mention `@` roles and executors, `@@` devices and bots, and `@@@` servers, and work with pinned messages, branches and side chats.
- [Routing](routing.md) — how PugPort picks an account and model: straight-line pacing, reset cards, expiring API credit, yielding when ahead of pace, technical cooldowns, prompt-cache warmth, Cursor model pools, routing profiles, pins, exclusions and route reasons.
- [Terminal (`pugport`)](terminal.md) — full-screen terminal chat and one-shot CLI commands (`ask`, `status`, `agents`, `tasks`, `cancel`, `doctor`, `open`, `node`), JSON fields, exit codes and `PATH` setup.
- [Remote servers and devices](remote-servers-and-devices.md) — Tailscale device nodes (`pugport node …`), connecting a server from the **Usage** page over an SSH tunnel, signing in to CLIs on the server, using `@@` and `@@@`, and sending files back and forth.
- [Inbox and notices](inbox-and-notices.md) — what appears in the **Inbox**, how the three-part notice works, and what each action button does.
- [Desktop, tray and sidebar](desktop-and-tray.md) — the system tray menu, overnight blackout, keep-awake, finish notifications, the sidebar (including hiding chats started by other agents) and search.
- [Permissions and safety](permissions-and-safety.md) — read-only versus writable tasks, caller permission inheritance, desktop-only approvals and “always allow”, MCP and HTTP task API limits, and the Windows sandbox learning mode.

For a one-page overview of everything in the app, see [Features](../FEATURES.md) and [Getting started](../GETTING-STARTED.md).
